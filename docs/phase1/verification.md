結果は仕様書 20.3 に従い「合格」「不合格」「未実施」「測定不能」で示す。開発機は Windows 10（正式対応外）であり、ここでの合格は正式対応の根拠にしない。

## 自動試験の結果

`dotnet test D2Translator.slnx` で 66 件すべて合格。うち実際の OS 機能を使う結合試験は次のとおり。

| 試験 | 内容 | 結果 |
| --- | --- | --- |
| ROI 切出しから OCR | 自プロセスの試験ウィンドウ（上下2行の英文）を WGC で取得し、下半分だけを ROI として OCR。下段の文だけが認識され、位置が取得画像の座標であること | 合格 |
| 取得頻度の間引き | 約 33 回毎秒で描画が変わるウィンドウを 5 回毎秒で取得し、間隔が 190ms 以上であること | 合格 |
| 対象消失 | UI スレッドで作った取得対象のウィンドウを閉じ、`TargetClosed` で終わること | 合格 |
| OCR | 描画した英文 1 行を Windows.Media.Ocr で正しく読み、`engineConfidence` が null であること | 合格 |

結合試験は対話デスクトップが必要なため、CI（環境変数 `CI=true`）ではスキップする。

## 検証で判明したこと

- **取得対象のスレッド依存**: UI スレッド（STA）で得た `GraphicsCaptureItem` を別スレッドから呼ぶと `RPC_E_WRONG_THREAD` になる。システムの選択 UI は UI スレッドで結果を返すため、取得セッションの作成と破棄、サイズ取得、イベント解除を作成元のスレッドで行うよう実装した（決定 D12）。フレームはフリースレッドのフレームプールで別スレッドに届く。
- **終了順序**: 上記のため、UI スレッドを止める終了処理より前に取得を停止する。メインウィンドウを閉じる時に取得停止を待ってから閉じる。
- **静止画面のフレーム**: WGC は描画が変わった時だけフレームを送る。静止したウィンドウでは「待機中」表示になるが、取得は継続している。
- **MSIX**: 未署名の MSIX は作成できた（286 ファイル）。署名とインストール、パッケージ識別情報下での OCR 動作は未実施。

### 実機確認の手順

1. `dotnet run --project src/D2Translator.App` でアプリを起動する。
2. Destiny 2 をボーダーレスまたはウィンドウ表示で起動し、チャット欄に文字が出ている状態にする。
3. 「対象を選択…」を押し、Windows の選択画面で Destiny 2 を選ぶ。
4. ROI 調整画面でチャット欄をドラッグで囲み、「試し読み」で認識結果を確認して「保存」する。チャットが消える場合は「プレビューを止める」を使う。
5. 「開始」を押し、メイン画面の「認識結果」と「診断」の値を確認する。「停止」でただちに止まることも確認する。
