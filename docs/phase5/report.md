## 見つけて直した不具合

| 不具合 | 原因と修正 | 見つけた経緯 |
| --- | --- | --- |
| 取得していない時にアプリを閉じると、例外で落ちていた | 終了時、取得の停止が同期的に終わると、ウィンドウを閉じる処理の中から `Close()` を呼び直して `InvalidOperationException` になっていた。これまでは未処理例外でプロセスが終わることで、結果的に閉じていた。閉じる処理を抜けてから閉じ直すよう修正 | 未処理例外を記録して処理を続けるようにしたところ、試験起動で終了しなくなり、診断記録に例外が残った |
| 取得中に対象ウィンドウの大きさが変わると、取得が止まっていた | フレームプールの作り直しをフレームの受信スレッドで行い、`RPC_E_WRONG_THREAD` で失敗していた（CAP01 で停止）。作成元のスレッドで作り直すよう修正。ゲームの解像度やウィンドウの大きさを変えた時に起こり得た | 耐久試験の模擬画面（枠付きウィンドウ）で毎回発生。試験 `Resizing_target_window_keeps_capturing_at_the_new_size` を加え、修正前に失敗、修正後に合格することを確かめた |
| 自分の発言の区切りが崩れると、システム表示として履歴から消えていた | 「宛て」の後はコロンしか受け付けていなかった。`.`、`・`、`•.` 等と読み落としも受け付け、行の組み立てで「宛て」の後に区切り記号以外をつなげない（D31） | 耐久試験で、模擬画面のフォントでは `[ファイアチーム]宛て:` が `ワァイアチーム]宛て.` と、小さな文字では `宛て: I` が `宛てコ` と読まれた |
| 小さな文字の英単語が漢字に化けていた | 日本語 OCR が `left` を「厄仕」等と読み、英語の正しい読みを消していた。英語 OCR が同じ位置を英字だけの、2 倍以上の文字数の語で読んでいれば英語を使う（D32） | 60 分の耐久試験（10 月 25 日追記） |
| P13 のメモリ増加が実際より大きく出ていた | 最大値との差で求めていたため、ガベージコレクション前の一時的な山を増加に数えていた。15 分ごとの中央値の差にした（D28） | 60 分の耐久試験の記録を見直した（10 月 25 日追記） |

## 試験

`dotnet test D2Translator.slnx` で 272 件すべて合格（Phase 4 の 241 件から 31 件増）。10 月 25 日の修正（D31、D32、P13 の求め方）の後は 276 件すべて合格。外部 API は偽の実装だけを使った。

| 観点 | 主な試験 |
| --- | --- |
| GPU 喪失 | 1 回の喪失から作り直して続けること、続けて失敗したら有限回で CAP01 で止まり対象を保つこと、復旧の待機中に停止できること |
| 取得 | 対象の大きさの変化で取得が止まらないこと（実際の WGC） |
| 診断記録 | 書込みと読み戻し、キーと認証ヘッダーの伏せ字、7 日の保持、合計の上限と古い順の削除、書きかけの行の読み飛ばし、ログの文字列引数は長さだけ、例外のメッセージと行番号を残さないこと、翻訳要求の記録に本文と名前がないこと |
| 集計 | p95 の順位、タグごとの区分、10 分平均の CPU、ウォームアップ後のメモリ増加、未処理例外の数、キャッシュ命中を除いた要求数、セッションの区別 |
| 非侵入性 | 下記 |
| 辞書 | 5MB を超えるファイルを読まずに断ること、10000 項目と 1 項目 2000 文字の上限 |
| 設定 | 新しい版の設定を読めない時に既定値で起動し、ファイルを書き換えないこと（元の版へ戻す場合） |
| 行の解析 | 「宛て」の後の区切りの誤読と読み落とし |
| 行の組み立て | 英単語の漢字への誤読、「宛て」の直後の誤読、英語 OCR の読みが短い記号列なら日本語を残すこと（10 月 25 日追記） |

## 非侵入性の設計点検

`tests/D2Translator.Compliance.Tests` は、アプリの出力と同じ依存物を集め、組立品のメタデータを読んで確かめる。

| 試験 | 内容 | 結果 |
| --- | --- | --- |
| 承認したネイティブ関数だけ | 本アプリの 9 組立品が呼ぶネイティブ関数が承認一覧の範囲内 | 実際に見つかった 10 個が承認一覧と一致 |
| 依存物に侵入的な関数がない | 配布する全組立品（WinRT、SharpGen、Vortice 等）に、入力生成（SendInput、PostMessage 等）、キー監視（SetWindowsHookEx、GetAsyncKeyState 等）、他プロセスへの接続とメモリの読み書き（OpenProcess、ReadProcessMemory、CreateRemoteThread 等）、ドライバーとサービス、パケット取得の関数がない | 依存物の 52 個に該当なし |
| マネージド API | 入力注入（InputInjector）、SendKeys、ソケット、動的なネイティブ読込み、他プロセスの列挙、プログラムやリンクの起動を参照しない | 該当なし |
| ゲームを名指ししない | 組立品の文字列にゲームのプロセス名や実行ファイル名がない | 該当なし |
| 送信先の固定 | 組立品の文字列にある URL は `https://api.openai.com/v1/responses` だけ | 一致 |
| 権限昇格を求めない | マニフェストが `asInvoker` | 一致 |

承認したネイティブ関数（理由は試験のコードに記載）: `user32.dll` の GetWindowLongPtrW、SetWindowLongPtrW、SetWindowDisplayAffinity、RegisterHotKey、UnregisterHotKey、GetForegroundWindow、GetWindowThreadProcessId、GetWindowTextW、GetClipboardSequenceNumber と、`d3d11.dll` の CreateDirect3D11DeviceFromDXGIDevice。いずれも自アプリのウィンドウ、登録型ホットキー、前面ウィンドウの判定、自アプリが書いたクリップボードの消去、取得画像の切出しに使う。
