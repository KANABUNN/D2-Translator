# 受入試験の証跡（A01〜A12）

仕様書 21 章の受入基準に対する、2026年10月24日時点の証跡。判定は仕様書 20.3 に従い「合格」「不合格」「未実施」「測定不能」に分け、疑似 API や模擬画面の結果を実 API や実機の結果として扱わない。部分的に確認できたものは「一部確認」と書き、合格とは扱わない。受入の完了日や承認の署名は記入しない（21.2）。

## 判定

| 受入 ID | 判定 | 証跡 | 残り |
| --- | --- | --- | --- |
| A01 C方式の両表示と 100 回切替 | 一部確認 | ゲーム上でオーバーレイ、独立ウィンドウ、相互切替、配置編集を利用者が確認（Phase 4）。表示切替の遅延を診断記録で計測（開発機で p95 72ms、10 回） | 取得と翻訳の処理中の 100 回切替で、履歴、ID、下書き、要求数に欠落と重複がないこと（T06） |
| A02 選択した ROI だけを OCR、対象消失と DPI 異常で停止 | 合格（開発機） | ROI 切出しと座標、対象の終了で CAP02、縦横比の変化で CAP03 の試験（`WgcCaptureTests`、`CaptureControllerTests`）。窓の大きさの変化で取得が止まらないこと（Phase 5 で修正、`Resizing_target_window_keeps_capturing_at_the_new_size`）。GPU 喪失で 3 回まで作り直し、それ以上は停止（`Device_loss_*`） | 正式対応構成（Windows 11）、混在 DPI、モニター切断（T02） |

| A04 P08、P09 を満たす | 未実施 | 採点用 TSV を作るツール（`D2Translator.Eval translate`、返信は `--ja-en`） | 評価者 2 名による 400 例と重要 100 例 |
| A05 日本語入力から英訳、編集、コピー、ゲーム入力 0 件 | 一部確認 | 利用者がゲームで英訳、コピー、貼り付け、送信を確認（Phase 4）。ゲームへの入力を生成するネイティブ関数と API が配布物に存在しないこと（`NonIntrusionTests`） | IME の変換確定と Ctrl+Enter の取り違え（T08） |
| A06 全経路で gpt-6-luna 固定、クラウド無効で送信 0 件、別 AI へ 0 件 | 合格（疑似 API） | 要求の固定値（`Request_uses_only_the_fixed_gpt_6_luna_profile`）、応答モデルの完全一致（`Unconfirmed_response_model_is_tr05`）、クラウド無効で送信 0 件（`Cloud_disabled_sends_nothing`）、設定の固定値改変で DATA01（`Tampered_*`）、送信先の URL が 1 つだけ（`The_only_network_endpoint_is_the_fixed_openai_responses_url`）。診断記録に要求・応答モデルを残す | 実 API での確認は Phase 3 の接続確認のみ（応答モデル `gpt-6-luna`、利用者による） |
| A07 設定と辞書の保存、検証、移行、削除、秘密の平文出力 0 件 | 合格（開発機） | 検証付きの原子的な保存と 1 世代のバックアップ、不正な設定と新しい版の設定を書き換えないこと、辞書の上限と制御文字、DPAPI の改ざん検出と削除、診断記録・ログ・例外記録に本文とキーが出ないこと（`DiagnosticsLogTests`、`Exception_record_*`、`Requests_are_recorded_for_diagnostics_without_text`） | 正式対応構成での確認 |
| A08 ホットキー競合時も停止と表示復帰、通常時に入力を奪わない | 一部確認 | 登録型ホットキーのみ（キーボードフックなし、`NonIntrusionTests`）。競合時は「未登録」と表示し、メイン画面のボタンで代替（Phase 4）。主要ボタンにアクセスキー（Phase 5）。オーバーレイはクリック透過でフォーカスを取らない（利用者が確認） | スクリーンリーダーでの読み上げ（T19） |

| A11 禁止した侵入方式が実装と依存物に存在しない、実機結果と未保証範囲の公開 | 合格（設計点検）、実機は一部確認 | 本アプリが呼ぶネイティブ関数 10 個が承認一覧と一致し、依存物を含めて入力生成、キー監視、他プロセスへの接続、メモリの読み書き、ドライバー、パケット取得の関数がないこと（`NonIntrusionTests`）。ゲームのプロセス名を持たず、昇格を求めない。Phase 1〜4 の実機確認で警告やブロックの報告なし。未保証の範囲は README と [残存制限一覧](../limitations.md) に記載 | 長期間の共存観察（T17） |

## 利用者に依頼する確認

| 順 | 確認 | 手順 | 対応 |
| --- | --- | --- | --- |
| 1 | 署名した MSIX のインストール | [配布、署名、更新](../distribution.md) の「個人で使う場合」で署名し、インストールして取得、OCR、翻訳、オーバーレイが動くこと。診断欄の「パッケージ識別情報」が「あり（MSIX）」になること | A12、U07 |
| 2 | 8 時間の実機試験 | ゲームと同時に 8 時間動かし、`dotnet run --project tools/D2Translator.Eval -- diagnostics --out p5-report.md` で判定表を作る | A10、P10〜P13 |
| 3 | 100 回の表示切替 | 取得と翻訳の処理中に Ctrl+Alt+O を 100 回押し、前後で受信履歴の件数、訳、返信の下書き、利用量の要求回数が変わらないこと | A01、T06 |
| 4 | IME とフォーカス | 返信画面で日本語の変換中に Enter と Ctrl+Enter を押し、変換の確定と英訳が取り違えられないこと。Ctrl+Alt+J で開いてゲームへ戻れること | A05、T07、T08 |
| 5 | 翻訳品質 | 受信用の英文 200 例と返信用の日本語 200 例を用意し、`D2Translator.Eval translate`（英日）と `translate --ja-en`（返信の日英）で作った TSV を評価者 2 名で採点する | A04、P08、P09 |
