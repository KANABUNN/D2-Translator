# D2 Chat Translator 拡張辞書

作成日: 2026-10-24 / 辞書版: `d2-chat-2026-10-24-v1` / `schemaVersion: 1`

**9,547語義、別表記込み10,988種類の照合表記**を収録した、英語チャット→日本語の辞書初版です。同じ英語の複数の意味も個別の語義として数えています。

## 収録内容

以下は重複を整理した後の主分類による件数です。公式データとコミュニティ資料の両方を参照する項目もあります。

|分野|語義数|
|---|---:|
|Bungie公式の日英名称を同一IDで対応付けた項目|8,795|
|一般のネット・ゲームチャットスラング|266|
|D2の募集・戦闘・ビルド・略称・呼びかけ等|475|
|既存サンプルから維持した語義|11|
|合計|9,547|

公式項目には武器、防具、パーク、MOD、サブクラス、スーパー・近接・グレネード・特性・かけら、アクティビティ、ロケーション、NPC、装備分類などが含まれます。素材、通貨、対戦モード、ファイアチーム検索ラベルも対象にしています。旧コンテンツの名称も含み、現在の入手・プレイ可否や推奨装備を意味しません。

俗語はLFG、役割分担、蘇生・全滅・火力、PvP、パーク略称、武器・防具の呼び名、ネット略語、Twitchのリアクション、謝罪・称賛・皮肉・荒い言葉などを収録しています。発言の強さや文脈による違いは`note`に記載しています。

## ファイルの使い分け

|ファイル|用途|
|---|---|
|`glossary-example.json`|全9,547語義。同梱辞書を置き換える完成データ。|
|`glossary-user.json`|追加分9,536語義のみ。現在の11語義サンプルに足すための利用者辞書。|
|`glossary-sources.json`|出典、公式データ版、取得URL・SHA-256、項目ごとの対応ID。アプリへ読み込ませる辞書ではありません。|
|`ambiguity-audit.json`|同じ照合表記に複数の語義がある場合の一覧。|
|`reference-only-common-names.json`|一般語との衝突が大きく自動照合から外した正式名称の参考一覧。|
|`validation-result.json`|実際のローダー・照合処理を使った検証結果と測定値。|
|`VALIDATION.md`|検証内容と限界の日本語説明。|
|`CLAUDE_HANDOFF.md`|Claudeへそのまま渡せる取り込み依頼。|
|`CURATION_NOTES.md`|俗語の出典確認水準、暫定訳、別表記、多義語の収集メモ。|

**全件版と追加分版を同時に使わないでください。** 全件版を同梱したうえで追加分版も利用者辞書として読み込むと、同じ用語が重複します。

## Claudeへの引き継ぎ

プログラム側の作業と並行できるよう、開発中のリポジトリと実際のアプリ設定には変更を加えず、この一式を成果物フォルダーに作成しました。取り込みは次のいずれか一方を選びます。

### A. 現在の11語義サンプルに追加する

1. 現在の同梱辞書が`example-2026-10-24`、11語義であることを確認します。確認用ハッシュは出典ファイル内にあります。
2. `AppDataLocation.UserGlossaryPath`が解決する保存先に、今回の`glossary-user.json`を置きます。既存の利用者辞書があれば先にバックアップし、内容を確認してから統合してください。既存内容を上書きしないでください。
3. アプリを再起動し、辞書の版・件数と読み込みエラーを確認します。未パッケージ版の既定保存先は`%LOCALAPPDATA%\D2ChatTranslator`です。MSIX版はパッケージのLocalState、`D2CT_DATA_DIR`を指定している環境はその指定先になるため、実際の保存先をコード側で確認してください。

この方式は現在のサンプルとの重複を避けた追加分です。今後同梱辞書が拡張済みになった場合は、そのまま再利用せず、取り込み済み項目との重複を確認してください。

### B. 正式な同梱辞書として取り込む

1. 今回の`glossary-example.json`を`src/D2Translator.DictionaryContext/Data/glossary-example.json`へ取り込みます。
2. 古い11語義サンプルは、既存の境界・語義テスト用の固定fixtureとして保持します。`GlossaryTests.cs`は件数11や照合結果1件を前提としているため、拡張辞書そのものの検証と分離してください。テストを単に緩くする変更は避けてください。
3. 利用者辞書に今回の追加分が登録されている場合は、バックアップしたうえで二重取り込みが起きない状態に整理します。現在の`GlossaryRuntime`は利用者辞書を上書きとして扱わず、同梱項目の前に連結する実装です。
4. 再ビルド・再起動して辞書件数、短文の注釈、翻訳入力の用語ヒントを確認します。同梱ファイルは埋め込みリソースなので、JSONを置き換えただけでは既存の実行ファイルへ反映されません。

## 品質と対応範囲

- 全件`pending`です。公式データの日英対応はIDで機械的に確認していますが、D2を理解する日英評価者による全件の意味・訳文確認は行っていません。アプリで「未確認の辞書」と表示されるのは現在の仕様に沿った動作です。
- 俗語の別表記には編集で追加した綴り違い・複数形も含み、全別名を1語ずつ出典ページで確認したわけではありません。一部のレイド用語は正式な日本語表示を確認できず、通称や効果説明で訳しています。確認水準は`CURATION_NOTES.md`に記録しています。
- 一般語にもなる単独の`well`や、誤誘導の大きい一部の固有名は自動照合から除外しています。`Well of Radiance`などの明確な表現は収録しています。名称の網羅性より、チャット中の誤誘導を減らすことを優先した箇所があります。
- DPS、OP、GL、FR、Discordなどは複数の語義を候補として保持します。辞書だけで文脈を断定しません。詳細は`ambiguity-audit.json`を参照してください。
- 今回は**英→日**の辞書です。確認時点の日本語返信・逆翻訳経路には辞書ヒントが渡されていないため、日→英で同じ辞書を活用するにはプログラム側の対応が必要です。`direction: both`に変えるだけでは逆引きされません。
- 全件がAPIへ送られる実装ではありません。本文に一致した注釈が用語ヒントとなり、現在は最大50件です。例文・出典情報はそのままAPIへ渡されません。
- 同じ表記に別々のtermIdがある場合、現在の照合器は複数の訳候補と先頭のtermIdだけを注釈に保持します。語義ごとの適用IDを厳密に追跡するには、プログラム側の改善が必要です。
- 原文と別表記は大文字小文字を区別せず、単語境界と最長一致で照合されます。一般文中の語義は翻訳側で確認する必要があります。`{n}`は1〜2桁の数字のみで、複数の異なる数値を一つの項目に入れるテンプレートは使っていません。
- プレイヤー名が辞書用語と同じ場合や、長い用語に短い話者名が含まれる場合の注釈の競合は、正式取り込み時にアプリ側でも確認してください。
- ゲーム実機、OCR、実際の翻訳API、画面上の使い勝手を含む確認は今回の対象外です。辞書読み込み成功は翻訳品質の合格を意味しません。

## 出典

公式名称は[Bungie Destiny 2 Manifest](https://www.bungie.net/Platform/Destiny2/Manifest/)から取得した英語・日本語データを使っています。取得時のManifest版は`245114.26.10.13.2000-1-bnet.66137`です。[公式APIスキーマ](https://bungie-net.github.io/multi/schema_Destiny-Definitions-DestinyInventoryItemDefinition.html)の定義に沿い、同一ハッシュの表示名を対応付けています。効果説明や数値の大量転載は行っていません。

俗語・コミュニティ略語は辞書サイト、公式説明、元のコミュニティ投稿・ガイドで用法を確認し、日本語訳、注記、短い例文を作成しました。出典の確認範囲、検索抜粋に限られた項目などの制限も`glossary-sources.json`に残しています。出典確認と人による最終レビューは別に扱っています。
