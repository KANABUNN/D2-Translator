# 決定記録

仕様書 23.2（D01〜D08）に続く決定を記録する。変更時は決定ID、理由、代替案、影響する受入基準、再試験の必要性を残す。

## D09 推論量を none に固定する

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026年10月24日 |
| 決定 | GPT-6 Luna の `reasoning.effort` を `none` に固定する。仕様書 6.3 と 12 章で検証用に選べるとした `low` は提供しない |
| 理由 | 発注者の指定による |
| 実装 | `OpenAIFixedProfile.ReasoningEffort`。設定ファイルの `translation.reasoningEffort` が `none` 以外なら固定値の改変として DATA01 にする |
| 影響 | Phase 3 の「none と low の評価」は none のみを評価する。T10 の「推論量変更」は対象外になる |
| 代替案 | 仕様書どおり `low` を検証用に残す。品質評価で none が基準を満たさない場合に再検討する |

## D10 取得対象の種別を推定しない

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026年10月24日 |
| 決定 | `GraphicsCapturePicker` はウィンドウとモニターのどちらを選んだかを返さないため、`capture.targetKind` は未設定のまま扱う |
| 理由 | 種別を推定するためにウィンドウを列挙すると、仕様書 7.1 の「ウィンドウの自動総当たり」に近づく |
| 影響 | フォーカス喪失時の停止（`capture.pauseOnFocusLoss`）は対象の HWND を特定できないと実装できない。Phase 4 で `CreateForWindow` による明示選択と合わせて再検討する |

## D12 取得対象への操作は作成元スレッドで行う

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026年10月24日 |
| 決定 | `GraphicsCaptureItem` の作成時の同期コンテキストを保持し、取得セッションの作成と破棄、サイズ取得、イベント解除をそのスレッドで実行する。フレームの受信と ROI 切出しはフリースレッドで行う |
| 理由 | Phase 1 の結合試験で、UI スレッドで作った取得対象を別スレッドから呼ぶと `RPC_E_WRONG_THREAD` になることを確認した |
| 影響 | UI スレッドを同期的に待たせると取得の停止が完了しない。終了時はウィンドウを閉じる前に取得を止める |

## D13 ゲームの表示言語と本文の言語の2言語で OCR する

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026年10月24日 |
| 決定 | 英語 OCR と日本語 OCR の両方で ROI を認識し、かな・漢字が2文字以上続く範囲は日本語、それ以外は英語の結果を使って行を組み立てる |
| 理由 | 実画面で、英語 OCR は日本語の行頭を記号列にし、日本語 OCR は英文の空白を落とすことを確認した。2言語の合成で文字誤り率が 63.6% から 4.2% に下がった（Phase 2 記録） |
| 影響 | OCR の処理時間がおよそ2倍になる（実画面の ROI で 1 回 60ms 前後）。日本語の言語機能がなければ英語だけに戻し、その旨を表示する |
| 代替案 | 色で行頭と本文を分ける（背景の影響が大きく不採用）。本文だけを切り出して英語 OCR にかける2段階方式（行の分割が日本語 OCR に依存し、英字の行を取りこぼすため不採用） |

## D14 本文中の名前は、画面に出た話者名から識別する

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026年10月24日 |
| 決定 | セッション中に画面に出た話者名と参加通知の名前を端末内の一時 ID に対応付ける。本文中の呼びかけは、表示名全体、末尾の数字を除いた名前、大文字で区切った2語以上の連なり（例: TheGreyWarden → grey warden）で探す。1語だけの部分一致は一般語と区別できないため使わない |
| Phase 3 での扱い | 見つけた呼びかけは翻訳前に一時 ID の記号へ置き換えて送り、訳文で元の名前へ戻す。名前を外部へ送らず、翻訳もさせない。見つからない名前は未知の語としてそのまま残すよう指示する |
| 理由 | 利用者の指摘による。仕様書 9.2 は話者欄の匿名化を定めるが、本文中の名前の扱いが未定だった |

## D15 他プレイヤーの発言のチャンネルは判別できるまで Unknown とする

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026年10月24日 |
| 決定 | 日本語クライアントでは、他プレイヤーの発言にチャンネル名が表示されず、話者名の色の濃淡だけが異なる。色の判定は背景の影響を受けやすいため、現時点では Unknown とする |

## D18 システム表示は受信履歴と翻訳の対象にしない

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026年10月24日 |
| 決定 | System と判定した行（参加通知、システムメッセージ、ROI に入ったチャット以外のゲーム内表示）は受信履歴に表示せず、翻訳の対象にもしない。件数だけを診断欄に示す |
| 内部での扱い | 追跡には引き続き使う。参加通知の名前は本文中の呼びかけの検出に使い、行の対応付けの目印にもなる |
| 理由 | 利用者の指定による。実機確認でチャット以外の画面表示が System として履歴を汚していた。会話の認識精度は十分で、システム表示を隠しても会話の取りこぼしの心配はないと利用者が判断した |
| 残る注意 | チャット以外の英字だけの表示が ROI に入ると、直前の発言の折り返しとして結合される可能性がある。ROI はチャット欄の履歴部分だけを囲む |

## D19 文脈では、判別できないチャンネルをどのチャンネルとも同じ会話とみなす

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026年10月24日 |
| 決定 | 仕様書 9.2 は同じセッションとチャンネルの原文を文脈にするが、他プレイヤーの発言はチャンネルが Unknown（D15）のため、Unknown はどのチャンネルとも同じ会話とみなす。判別できた異なるチャンネル（例: クランとファイアチーム）は混ぜない |

## D23 薄れていくチャットの読みを訂正として採用しない

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026年10月24日 |
| 決定 | (1) 他プレイヤーの発言の区切りとして、コロンの誤読（`•.`、`・`、`.` 等）も受け付け、本文の先頭に残った区切りの誤読を取り除く。`:)` のように記号の後に空白がないものは残す。(2) 確定後の読みの変化は、初回観測から 5 秒以内で、かつ記号の混入が増えない場合だけ訂正として採用する。(3) 一時 ID は発言の話者と、`名前#識別番号` の形で読めた名前だけに振り、本文中の呼びかけの検出には後者だけを使う |
| 理由 | Phase 3 の実機確認で、チャットが薄れるとコロンが `•.` と読まれ、それが訂正として採用されて本文と訳を汚した。また、チャット以外の表示から拾った文字列が話者として登録され、一般語を名前と誤認する危険があった |
| 影響 | 5 秒を過ぎてからの正しい訂正も採用されない。初回の読みは表示直後の鮮明な状態で行われるため、影響は小さいと判断した |
## D24 オーバーレイは、ゲームが前面にない時に前面ウィンドウのタイトルで判断して隠す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026年10月24日 |
| 決定 | 前面ウィンドウのタイトルを取得対象の名前（選択 UI が返す表示名）と比べ、一度でも一致したら対象をウィンドウとみなす。その後、ゲームでも自アプリでもないウィンドウが前面になったらオーバーレイを隠す（`capture.pauseOnFocusLoss`、既定で有効）。一致しない対象（モニターを選んだ場合等）では隠さない |
| 理由 | 選択 UI は HWND を返さない（D10）。ウィンドウを列挙せずに、前面の 1 ウィンドウのタイトルだけを比較に使う。タイトルは保存、記録、送信しない |
| 影響 | ウィンドウを選んだ取得は対象を限定できるため、ゲームが前面でなくても取得は止めない（仕様書 4.2 の停止は対象を限定できない場合）。モニター取得を明示的に判別して停止する処理は未実装 |

## D25 透過オーバーレイの画面取得からの除外は、この環境では使えない

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026年10月24日 |
| 決定 | `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` を試し、結果を診断欄に表示する。開発機（Windows 10 22H2）では、WPF の透過ウィンドウ（レイヤードウィンドウ）に対してエラー 8 で失敗した |
| 影響 | ウィンドウを選んで取得している場合、WGC は対象ウィンドウの内容だけを取得するため、オーバーレイは映り込まない。モニター全体を取得している場合は映り込み得るため、ROI と重ならない位置に置くよう案内し、取得した行に表示した訳文が現れたら通知する |
| 今後 | Windows 11 での成否を確認する。必要なら、レイヤードウィンドウを使わない描画（DWM による透過）を検討する |

## D26 設定画面の反映の時点

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026年10月24日 |
| 決定 | 表示、取得の頻度、返信、クリップボード、ホットキーは「適用」で反映する。翻訳のタブは送信内容の確認と API キーを伴うため、操作した時点で反映する。OCR の言語と拡大倍率は取得を止めて適用する必要があるため、次回起動時に反映する。取得の頻度は次に「開始」した時から反映する |
| 補足 | 開発時の確認で利用者の設定を書き換えないよう、環境変数 `D2CT_DATA_DIR` でデータの保存先を切り替えられるようにした |
